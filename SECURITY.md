# Security Policy

The following table indicates which versions of this project currently

release, only the most recent tagged version is supported.

|-|-|

## Reporting a Vulnerability

Security vulnerabilities must be reported privately and must not be disclosed
through public GitHub issues, discussions, or pull requests, in order to
protect users prior to the availability of a remediation.

To report a vulnerability, send a detailed description to:

mandarkulkarni10110@gmail.com

A report should include, to the extent available:

1. A description of the vulnerability and its potential impact.
2. Steps to reproduce the issue, including affected file(s) or function(s).
3. The version or commit hash in which the vulnerability was identified.
4. Any known mitigations.

### Response Process

Upon receipt of a report, the maintainers will:

1. Acknowledge receipt within **5 business days**.
2. Provide an initial assessment of severity and validity within **10
business days**.
3. Issue a remediation or coordinate a disclosure timeline with the reporter
once a fix is available.

Reporters who wish to remain credited for their disclosure will be
acknowledged in the release notes accompanying the fix, unless anonymity is
explicitly requested.

## Scope

This policy applies to the source code, dependencies, and data-handling
logic contained within this repository. It does not extend to third-party
tools invoked by this project (e.g., AutoDock Vina, PyMOL), for which
vulnerabilities should be reported to their respective maintainers.
